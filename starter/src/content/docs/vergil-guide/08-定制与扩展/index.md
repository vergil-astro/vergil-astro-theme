# 定制与扩展

前面几章讲的是「怎么用」，这一章讲「怎么改」。

如果你只是写文章、配置站点，不需要看这里。如果你想改组件样式、加新指令、给主题添功能，这里说明主题内部的几个约定——顺着它们改，改动不容易互相打架。这些都是改主题本身，要在主题仓库里做，不在你的站点里，见下一节。

## 在哪里改

你的站点装的是 npm 包 `@vergil-astro/theme`，站点里只放内容、图片和配置。组件、页面、样式、指令、界面语言都在主题包里。

- **不要改 `node_modules`**：主题的代码就在 `node_modules/@vergil-astro/theme/src/` 下，但在那里改留不住，升级主题或重装依赖就会被覆盖。
- **只想换外观**：做一个皮肤。皮肤放在站点根目录的 `skins/` 下，不用碰主题代码，见[界面皮肤](/docs/vergil-guide/02-站点配置/界面皮肤/)和[皮肤与配色接口](/docs/vergil-guide/08-定制与扩展/皮肤与配色接口/)。
- **改组件、加指令、加界面语言、加相册主题**：在主题仓库里改。克隆仓库，装好依赖后启动：

  ```bash
  git clone https://github.com/vergil-astro/vergil-astro-theme.git
  cd vergil-astro-theme
  pnpm install && pnpm dev
  ```

  跑起来的是仓库里的示例站 `starter/`，它用的就是仓库里的主题源码，改了立刻能看到。改好后提 PR 合进主题，所有站点升级主题后都能用上。

本章提到的 `src/styles/`、`src/plugins/`、`src/components/` 这类路径都在主题仓库里，你的站点里没有。只有讲皮肤时说的 `skins/` 和 `src/data/config/` 在站点里。

## 这一章包含

- **[设计 Token](/docs/vergil-guide/08-定制与扩展/设计token/)** — 圆角、阴影、层级、动效时长的统一标度。改样式前先看有没有现成的 token，不要另造数值。
- **[组件与结构](/docs/vergil-guide/08-定制与扩展/组件与结构/)** — 布局、共享组件、样式文件怎么组织，新增组件该放哪。
- **[皮肤与配色接口](/docs/vergil-guide/08-定制与扩展/皮肤与配色接口/)** — 做皮肤、做配色时的目录和清单格式，以及皮肤可以依赖的 token、挂钩和变量。

界面文案的多语言机制在 [界面语言](/docs/vergil-guide/06-功能配置/界面语言/)，无障碍和动效的约定在 [无障碍与动效](/docs/vergil-guide/06-功能配置/无障碍与动效/)，这两章虽然归在功能配置下，但同样是定制时要遵守的约定。

## 一个原则

主题里凡是重复三次以上的东西，基本都抽成了共享的：文案抽成字典、数值抽成 token、markup 抽成组件。

改动时优先复用这些共享物，而不是在局部复制一份改。局部复制当下最省事，但下次有人改共享的那份时，你这份不会跟着变，久了就会出现同一个东西在不同页面长得不一样。主题早期的上下篇导航、卡片外壳都吃过这个亏。
