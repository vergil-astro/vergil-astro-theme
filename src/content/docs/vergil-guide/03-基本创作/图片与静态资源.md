# 图片与静态资源

Vergil 沿用 Astro 官方的做法：图片集中放在 `src/` 下，构建时自动压缩、转 WebP、写入宽高。在此基础上加了一个 `@img/` 别名，不管文章放在哪一层目录，引用路径都一样短。

## 一条规则

**图片放在 `src/assets/img/<载体>/<内容名>/` 下，正文里写 `@img/<载体>/<内容名>/<图片名>`。**

载体就是 `src/content/` 下的目录名：`blog`、`projects`、`pages`、`docs`。内容名是文件名去掉 `.md`，放在专栏子目录里的文章也只取文件名，和文章 URL 的规则一致。文档是例外：不同知识库里常有同名文件，所以按知识库分，写 `@img/docs/<知识库>/<图片名>`。

```
src/assets/img/
├── blog/
│   ├── starrocks-compaction/
│   │   └── trigger-flow.png
│   └── 短链服务/
│       └── architecture.png
└── projects/
    └── agoradb/
        └── architecture.png

src/content/blog/
├── starrocks-compaction.md      ![](@img/blog/starrocks-compaction/trigger-flow.png)
└── 系统设计/
    └── 短链服务.md              ![](@img/blog/短链服务/architecture.png)
```

`@img/` 代表 `src/assets/img/`，定义在 `tsconfig.json` 的 `paths` 里。写法和文章所在的目录无关，文章挪进专栏子目录，路径也不用改。

## 引用写法

正文：

```markdown
![Compaction 触发流程](@img/blog/starrocks-compaction/trigger-flow.png)
```

frontmatter 里声明为图片类型的字段也能用，同样会被优化：

```markdown
---
seo:
  image:
    src: '@img/blog/starrocks-compaction/cover.jpg'
---
```

支持的字段：博客、页面、项目的 `seo.image.src`，知识库 `_meta.md` 的 `cover`，相册的 `cover` 和 `images[].src`。

构建后图片会输出到 `/_astro/`，文件名带内容哈希，比如 `trigger-flow.TDdz2LGr.webp`，并自动带上 `width`、`height` 和 `loading="lazy"`。

## 例外：只接受字符串路径的地方

下面这些位置不经过 Astro 的图片处理，`@img/` 写法无效。图片放到 `public/assets/`，用 `/assets/` 开头的路径引用：

- 博客和文档的封面 `banner`
- 专栏的 `cover`、简历的 `avatar`
- 图文动态 JSON 里的 `images`
- 想法正文里的图片
- 内容指令里的 `src`，比如 `::image`、`gallery`、`posters`

```markdown
---
banner: /assets/topic/java.svg
---
```

`public/assets/` 里的文件原样输出，不会被压缩，适合放多篇文章共用的小图标和 SVG。

## 站点图片

头像、首页 Hero 图在 `src/data/site-config.ts` 里用 `import` 引入，放在 `src/assets/images/`，替换同名文件即可。favicon、分享卡片图这类需要固定地址的文件放在 `public/` 根目录。

## 编辑器预览

Typora、VS Code 的 Markdown 预览不认识 `@img/` 别名，写作时这类图片显示不出来，在 `pnpm dev` 里能正常看到。

## 用 `pnpm images:check` 体检

仓库自带一个图片检查脚本，只读不写，不会删除或移动任何文件：

```bash
pnpm images:check
```

它会报告五类问题：

| 类别 | 含义 | 是否让命令失败 |
| --- | --- | --- |
| 引用失效 | 内容里写了图片路径，但对应文件不存在 | 是 |
| 可以迁移 | 正文引用了 `public/` 下的图，挪到 `src/assets/img/` 能被优化 | 否 |
| 内容重复 | 几个文件的内容完全相同 | 否 |
| 体积过大 | 单张超过 500KB | 否 |
| 暂未引用 | 没有在任何源码或内容里找到这个文件名 | 否 |

只有「引用失效」会让命令以非零状态退出，适合放进 CI。其余几类只是提示，尤其是「暂未引用」的图，可能是留着以后用的，脚本不会建议删除。

体积阈值可以调：

```bash
pnpm images:check --max-kb 800
```

:::callout{type="note" title="「暂未引用」是按文件名匹配的"}
脚本判断一张图有没有被用到，是看它的文件名有没有出现在源码或内容里。用字符串拼接出来的路径（比如 `` `post-${n}.jpg` ``）检测不到，会被误报成暂未引用。
:::
