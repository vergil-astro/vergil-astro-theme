# 图片与静态资源

Vergil 沿用 Astro 官方的做法：图片集中存放，构建时自动压缩、转 WebP、写入宽高。在此基础上加了一个 `@img/` 别名，不管文章放在哪一层目录，引用路径都一样。

## 两种引用方式

| 方式 | 写法 | 图片放在 | 构建时 | 用在哪 |
| --- | --- | --- | --- | --- |
| `@img/` 别名 | `@img/blog/my-post/a.png` | `src/assets/img/` | 压缩、转 WebP、写入宽高 | 正文图片，以及声明为图片类型的字段 |
| `/assets/` 绝对路径 | `/assets/site/avatar.jpg` | `public/assets/` | 原样输出 | 只接受字符串路径的字段、站点配置、内容指令 |

能用 `@img/` 的地方都用 `@img/`。外链 `https://...` 在两类位置都能用。

## 目录全景

```
src/assets/img/                  ← @img/ 指向这里
├── blog/<文章名>/                  博客文章的图
├── projects/<项目名>/              项目的图
├── pages/<页面名>/                 独立页面的图，比如 pages/about/
├── docs/<知识库>/                  知识库的图，含 _meta.md 的封面
└── albums/<相册名>/                相册的封面和照片

public/
├── favicon.svg、manifest.json      必须放在根路径的文件
└── assets/                       ← /assets/ 指向这里
    ├── site/                        站点图：头像、分享卡片图
    ├── defaults/                    主题的默认图：开屏背景、默认封面，没配置时使用
    └── <自己建>/                    比如 topic/ 放文章封面图标，按用途命名
```

`src/assets/img/` 下的目录名和 `src/content/` 下的目录名一一对应。`public/assets/` 下除了 `site/` 和 `defaults/`，其他子目录按用途自己建。

## `@img/`：内容里的图

**图片放在 `src/assets/img/<载体>/<内容名>/`，引用写 `@img/<载体>/<内容名>/<图片名>`。**

- **载体**是 `src/content/` 下的目录名：`blog`、`projects`、`pages`、`docs`、`albums`。
- **内容名**是文件名去掉 `.md`。放在专栏子目录里的文章也只取文件名，和文章 URL 的规则一致。
- **文档按知识库分**：不同知识库里常有同名文件，所以写 `@img/docs/<知识库>/<图片名>`。

```
src/assets/img/blog/
├── starrocks-compaction/
│   └── trigger-flow.png
└── 短链服务/
    └── architecture.png

src/content/blog/
├── starrocks-compaction.md      ![](@img/blog/starrocks-compaction/trigger-flow.png)
└── 系统设计/
    └── 短链服务.md              ![](@img/blog/短链服务/architecture.png)
```

主题自带的两篇示例文章就是这样放的，可以照着改：[一、先想清楚你要发布什么](/blog/01-choose-content-type/)（普通文章，含 `seo.image`），[媒体嵌入指令](/blog/directives-03-media/)（专栏子目录里的文章）。

`@img/` 定义在 `tsconfig.json` 的 `paths` 里，由 Astro 原生解析。写法和文章所在的目录无关，文章挪进专栏子目录，路径也不用改。

正文里：

```markdown
![Compaction 触发流程](@img/blog/starrocks-compaction/trigger-flow.png)
```

frontmatter 里声明为图片类型的字段也能用。`@` 开头的值在 YAML 里**必须加引号**，否则构建报错：

```markdown
---
seo:
  image:
    src: '@img/blog/starrocks-compaction/cover.jpg'
---
```

支持 `@img/` 的字段：博客、页面、项目的 `seo.image.src`，知识库 `_meta.md` 的 `cover`，相册的 `cover` 和 `images[].src`。

构建后图片输出到 `/_astro/`，文件名带内容哈希，比如 `trigger-flow.TDdz2LGr.webp`，并自动带上 `width`、`height` 和 `loading="lazy"`。

## `/assets/`：只接受字符串路径的地方

下面这些位置不经过 Astro 的图片处理，`@img/` 写法无效，图片要放在 `public/assets/` 下：

| 位置 | 示例 |
| --- | --- |
| 博客和文档的封面 `banner` | `banner: /assets/topic/java.svg` |
| 专栏的 `cover` | `cover: /assets/series/系统设计.png` |
| 简历的 `avatar` | `avatar: /assets/site/avatar.jpg` |
| 图文动态 JSON 里的 `images` | `"images": ["/assets/moments/desk.jpg"]` |
| 想法正文里的图片 | `![](/assets/thoughts/a.jpg)` |
| 内容指令里的 `src`（`image`、`gallery`、`posters`、`photo` 等） | `::image{src="/assets/blog/my-post/a.png"}` |
| 站点配置：头像、分享卡片图、开屏背景 | `src: '/assets/site/avatar.jpg'` |

`public/assets/` 里的文件原样输出，不会被压缩，适合放多篇文章共用的小图标和 SVG。

站点图片都在配置里写路径：

| 图片 | 文件 | 在哪配置 |
| --- | --- | --- |
| 头像（侧栏、动态页、简历共用） | `public/assets/site/avatar.jpg` | `src/data/site-config.ts` 的 `avatar` |
| 分享卡片图 | `public/assets/site/vergil-preview.jpg` | `src/data/config/identity.ts` 的 `image` |
| 开屏背景 | `public/assets/defaults/splash-*.webp` | `src/data/config/splash.ts` 的 `backgroundImage` |

换成自己的图，同名覆盖，或者把配置里的路径改成你自己的文件。

## 编辑器预览

Typora、VS Code 的 Markdown 预览不认识 `@img/` 别名，写作时这类图片显示不出来，在 `pnpm dev` 里能正常看到。

## 用 `pnpm images:organize` 整理

已经写好的内容里，图片如果还散在别处（相对路径、`public/` 下），运行一次就能按上面的规则整理好：

```bash
pnpm images:organize
```

它会：

1. 找出博客、项目、页面、知识库、相册里还没用 `@img/` 的本地图片引用，包括正文图片和 `seo.image.src`、`cover`、相册 `images[].src`
2. 把图片**移动**到 `src/assets/img/<载体>/<内容名>/`
3. 把引用改成 `@img/...`，frontmatter 里自动加引号
4. 最后自动跑一次 `pnpm images:check`

几种特殊情况：

| 情况 | 处理 |
| --- | --- |
| 同一张图被多条内容引用 | 移给第一条，其余各复制一份；同一知识库内只放一份 |
| 图片还被代码、配置或 `banner` 这类字符串字段引用 | 只复制，不移动，原文件留在原处 |
| 目标位置已有同名但内容不同的文件 | 自动改名，比如 `flow-1.png` |
| 引用的文件不存在 | 跳过，在结果里列出来 |

不会做的事：不删除任何图片，没被引用的图原地不动；不处理 `banner`、指令、图文动态、想法这些只接受字符串路径的地方；代码块和行内代码里的写法示例不动。

命令直接修改文件，建议在 git 工作区干净的时候运行，整理完用 `git diff` 看一遍改动。已经整理好的内容再运行一次，不会有任何变化。

## 用 `pnpm images:check` 体检

仓库自带一个图片检查脚本，只读不写，不会删除或移动任何文件：

```bash
pnpm images:check
```

它会报告五类问题：

| 类别 | 含义 | 是否让命令失败 |
| --- | --- | --- |
| 引用失效 | 内容里写了图片路径，但对应文件不存在 | 是 |
| 可以迁移 | 正文引用了 `public/` 下的图，挪到 `src/assets/img/` 能被优化 | 否 |
| 内容重复 | 几个文件的内容完全相同 | 否 |
| 体积过大 | 单张超过 500KB | 否 |
| 暂未引用 | 没有在任何源码或内容里找到这个文件名 | 否 |

只有「引用失效」会让命令以非零状态退出，适合放进 CI。其余几类只是提示，尤其是「暂未引用」的图，可能是留着以后用的，脚本不会建议删除。

体积阈值默认 500KB，要调整就改 `scripts/check-images.mjs` 顶部的 `MAX_KB`。

:::callout{type="note" title="「暂未引用」是按文件名匹配的"}
脚本判断一张图有没有被用到，是看它的文件名有没有出现在源码或内容里。用字符串拼接出来的路径（比如 `` `post-${n}.jpg` ``）检测不到，会被误报成暂未引用。
:::
