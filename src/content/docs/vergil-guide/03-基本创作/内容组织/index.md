# 内容组织

当你的文章越来越多时，需要一套系统来组织和检索内容。Vergil 提供三种组织方式：**专栏**、**分类**和**标签**。

## 三种方式的区别

| 方式 | 层级 | 数量 | 作用 |
|------|------|------|------|
| **专栏** | 文章 → 专栏 | 一篇文章只属于一个专栏 | 将系列文章串联成册 |
| **分类** | 文章 → 分类 | 一篇文章只属于一个分类 | 按大主题分区 |
| **标签** | 文章 ↔ 标签 | 一篇文章可打多个标签 | 按关键词交叉检索 |

---

## 专栏 —— 系列文章

**什么时候用：**

- 你计划写一个多篇文章组成的系列，比如"从零学 Astro"共 10 篇
- 这些文章有先后顺序，读者应该按顺序阅读
- 你想在文章底部展示"上一篇 / 下一篇"导航

**如何使用：**

在博客文章的信息头中声明：

```markdown
---
title: 第 1 篇：选择主题
series: 搭建博客系列
---
```

多篇文章使用相同的 `series` 值，就自动归属于同一个专栏。属于同一专栏的文章，详情页底部会自动显示系列导航。

**命名建议：** 使用清晰的主题名称，如"Astro 入门教程"、"摄影后期指南"。文章标题建议加上序号。

### 用目录管理专栏文章

文章多起来之后，`src/content/blog/` 下会堆上百个文件，想改专栏里的某一篇很难找。

专栏可以认领一个目录，把自己的文章收进去。先在 `src/content/series/` 下建专栏定义文件：

```markdown
---
name: 系统设计专栏
description: 从需求分析到架构取舍，一题一篇。
dir: 系统设计
---
```

然后把这个专栏的文章都放进 `src/content/blog/系统设计/`：

```
src/content/blog/
├── 系统设计/
│   ├── 短链服务.md
│   ├── 分布式ID生成器.md
│   └── 一致性哈希.md
└── 其他文章.md
```

这个目录下的文章**自动属于这个专栏，不用再逐篇写 `series`**。文章里仍然可以写 `series`，写了就以文章为准，目录只是默认值。

:::callout{type="tip" title="目录不影响文章地址"}
`src/content/blog/系统设计/短链服务.md` 的地址仍然是 `/blog/短链服务/`，目录名不进 URL。所以把已经发布的文章挪进目录，不会让任何旧链接失效。
:::

需要注意两点：

- `dir` 只能是**一级目录**，填了斜杠会在构建时报错。
- 既然目录不进 URL，不同目录下也**不能有同名文件**。`blog/a.md` 和 `blog/系统设计/a.md` 会指向同一个地址，构建会直接报错并指出是哪两个文件，不会悄悄覆盖。

不填 `dir` 就是原来的方式，文章散在 `src/content/blog/` 下，靠每篇的 `series` 字段归属。

## 分类 —— 主题归类

**什么时候用：**

- 你的文章可以归入几个明确的主题方向
- 每个主题下的文章之间没有阅读顺序
- 你想在网站顶部或侧边栏展示分类导航

**如何使用：**

```markdown
---
title: React Hooks 指南
categories:
  - 技术
---
```

**命名建议：** 使用简洁的主题词，如"技术"、"生活"、"随笔"、"摄影"。分类数量建议控制在 3-6 个。

---

## 标签 —— 关键词标记

**什么时候用：**

- 你想给文章打上更具体的关键词
- 一篇文章可以同时涉及多个话题
- 你希望通过关键词找到相关的文章

**如何使用：**

```markdown
---
title: React Hooks 指南
tags:
  - React
  - JavaScript
  - 前端
  - 教程
---
```

**命名规范：**

- 使用通用、简洁的词汇
- 保持命名一致性（统一用"前端"，不要混用"Front-end"）
- 每篇文章 2-5 个标签

---

## 对比总结

| 场景 | 推荐方式 |
|------|---------|
| "我写了一组有顺序的教程" | 专栏 |
| "我的文章属于几个大方向" | 分类 |
| "我想给文章打多个关键词" | 标签 |
| "我想展示系列导航" | 专栏 |
| "我想做交叉检索" | 标签 |

:::callout{type="tip"}
三者可以组合使用。一篇博客文章可以同时属于一个专栏、一个分类和多个标签，这是最常见的用法。
:::
